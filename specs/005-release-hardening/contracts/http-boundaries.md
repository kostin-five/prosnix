# Контракт HTTP-границ hardening

## `GET /health`

- Назначение: liveness процесса.
- Успех: `200 {"status":"ok"}`.
- Не обращается к БД или внешним сервисам.

## `GET /ready`

- Назначение: readiness для Render и smoke-test.
- Успех: `200 {"status":"ready"}` после успешной ограниченной проверки БД.
- Отказ/timeout: `503 {"error":"service_unavailable","requestId":"..."}`.
- Ответ не содержит исходное исключение, hostname или строку подключения.

## Защитные ответы

Все API/internal/health/readiness ответы включают минимум:

- `X-Content-Type-Options: nosniff`;
- `Referrer-Policy` с запретом раскрытия чувствительного пути;
- `Cache-Control: no-store` для auth и `/api/*`;
- остальные совместимые заголовки формируются стандартной политикой сервера.

## Ограничения запроса

- глобальное тело HTTP-запроса: не более 32 КиБ;
- `initData`: не более 8 КиБ;
- Telegram auth: ограниченное число попыток на IP за минуту;
- Coach: ограниченное число загрузок на IP/сессию за минуту;
- отказ по частоте: HTTP 429 до выполнения handler;
- отказ по размеру: HTTP 413 или 400 согласно границе валидации.

Точные лимиты конфигурируются только серверными переменными и не являются публичным обещанием API.
