# Модель данных: Релизное усиление MVP

## Постоянные данные

Новых сущностей и миграций нет. Существующие пользователи, wake-сессии, результаты, расписания,
уведомления, idempotency records и AI cache не меняются.

## Эфемерные runtime-состояния

### Состояние готовности

- `status`: `ready | unavailable`;
- `checkedAt`: серверное время только для журнала, не обязательно в публичном ответе;
- `dependency`: нейтральная категория `database` только в структурированном журнале;
- `durationMs`: длительность проверки для наблюдаемости.

Переходы: каждый запрос вычисляет состояние заново; значение не сохраняется и не влияет на
пользовательские данные.

### Счётчик ограничения частоты

- ключ: IP для Telegram auth, IP/сессия для Coach в рамках одного API instance;
- окно: короткий фиксированный интервал;
- количество: число принятых попыток;
- срок: автоматически истекает после окна.

Счётчики не являются продуктовой аналитикой, не содержат body/initData и не сохраняются в БД.

### Состояние завершения процесса

- `idle`: сигнал ещё не получен;
- `closing`: закрытие сервера начато, повторные сигналы используют тот же promise;
- `closed`: ресурсы освобождены;
- `deadline_exceeded`: процесс завершает работу с ошибкой после безопасного ограничения времени.

## Правила приватности

- Readiness и lifecycle logs не содержат URL БД, cookie или exception message для клиента.
- Rate-limit не сохраняет Telegram initData и пользовательские ответы.
- Playwright artifacts создаются только из тестовых данных и хранятся ограниченный срок.
