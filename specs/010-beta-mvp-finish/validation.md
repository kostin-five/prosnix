**Дата:** 6 сентября 2026 года
**Ветка:** `dev`
**Commit реализации:** `74d61fe`
**Статус:** реализация проверена локально и закоммичена; production-выпуск не подтверждён

## Что проверено

- фирменный wordmark и Beta status на основных пользовательских экранах;
- отсутствие пересечения wordmark и счётчика сессий на ширине 320 px;
- дневной график главной из серверного `dailyTrend`, включая `+`, `0`, отрицательные значения и `n`;
- понятное пустое, loading и error состояние графика;
- раннее предупреждение до трёх сессий без provider-вызова;
- явное `confirmEarly`, однократный дневной provider-вызов, cache и конкурентное объединение;
- обезличенные trend signals без session/evidence IDs;
- строгий AI prompt и отклонение ответа, повторяющего уже показанный средний прирост;
- содержательный deterministic fallback без технического имени provider и слова «заглушка»;
- совместимость текущей таблицы AI cache без migration.

## Ручная проверка перед выпуском

1. Просмотреть главную в реальном Telegram iOS: wordmark, счётчик и график после нескольких сессий.
2. Проверить обычный отчёт при 3+ сессиях и ранний подтверждённый отчёт на тестовом пользователе.
3. По privacy-safe Render logs подтвердить один provider-вызов и отсутствие текста/identity в логах.
4. Дождаться зелёного CI точного commit SHA.
5. Только отдельным решением владельца выполнить совместимый deploy API и web.

## Остаточные риски

- запас initial bundle менее 1 КиБ: следующий UI-код следует выносить в lazy chunks;
- один process-local in-flight lock достаточен для текущего одного API instance, но не для будущего
  горизонтального масштабирования;
- Chromium E2E не заменяет ручной Telegram Android WebView тест;
- качество provider-текста нужно наблюдать на реальных агрегатах, сохраняя строгий fallback.
