# Исследование: Продуктовая админ-панель

## Источник метрик

**Решение**: считать показатели непосредственно из канонических PostgreSQL-таблиц при запросе владельца.

**Обоснование**: текущий масштаб мал, панель используется редко, а прямые агрегаты сохраняют воспроизводимость и не создают второй источник истины.

**Альтернативы**: внешний analytics SDK отклонён из-за privacy и стоимости; отдельная витрина/worker отложены до подтверждённой проблемы производительности.

## Когортная воронка

**Решение**: закреплять когорту по времени создания сессии и ограничивать все последующие события правой границей периода.

**Обоснование**: числители остаются вложенными и проценты можно честно сравнивать.

**Альтернативы**: независимый подсчёт событий по их собственным датам отклонён, потому что completed может превысить started у границы периода.

## Временная зона

**Решение**: административные когорты и timeline используют UTC.

**Обоснование**: пользователи могут иметь разные часовые пояса; одна серверная граница воспроизводима и совпадает с сохранёнными timestamps.

**Альтернативы**: timezone владельца и timezone каждого пользователя отклонены для MVP из-за неоднозначных общих дневных итогов.

## Privacy

**Решение**: возвращать только фиксированные агрегаты, без raw rows, UUID, Telegram ID, evidence IDs и произвольных текстов.

**Обоснование**: владельцу нужны продуктовые решения, а не просмотр поведения конкретного человека.

**Альтернативы**: drill-down до пользователей и экспорт raw CSV исключены из scope.

## Визуализация

**Решение**: карточки, CSS progress bars и компактные таблицы вместо chart library.

**Обоснование**: админ-экран ленивый, но проект уже почти исчерпал initial bundle budget; простая визуализация быстрее и доступнее на мобильном экране.

**Альтернативы**: Recharts и другие графические зависимости отклонены как избыточные.

## Ошибки

**Решение**: показывать delivery failures из сохранённых таблиц, а общие HTTP/runtime ошибки оставлять в privacy-safe Render logs.

**Обоснование**: проект пока не хранит operational events; добавлять новую таблицу и запись на error path ради одной панели рискованно.

**Альтернативы**: новый error-event store и интеграция с Render API отложены до отдельного observability этапа.
