# Модель данных

## Изменения

Схема PostgreSQL, HTTP payload и список task IDs не меняются.

### Кандидат назначения

- `protocolKey`: новый стабильный ключ состава;
- `protocolVersion`: `7` для новых кандидатов;
- `strategyVersion`: новая версия learning/adaptive/fallback стратегии;
- `steps`: пять упорядоченных существующих task IDs до персонализации;
- `hypothesis`: непричинное описание того, что проверяется.

### Персонализированное назначение

- использует существующий snapshot возможностей;
- удаляет запрещённые и недоступные шаги;
- не добавляет task ID, отсутствующий в допустимом пуле;
- сохраняет мягкое движение раньше приседаний.

### Персональный отчёт

Серверные поля `evidenceCount` и `source` сохраняются без изменений. Меняется только их
отображение: техническая подпись больше не выводится отдельной строкой.

## Переходы и совместимость

- Новые сессии получают version 7 после выпуска кода.
- Сессии versions 1–6 продолжают выполняться по сохранённым `steps`.
- Исторические назначения и наблюдения не пересчитываются и не переписываются.
