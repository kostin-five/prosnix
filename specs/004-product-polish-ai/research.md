# Исследование: Надёжный UX и AI Wake Coach

## DeepSeek transport

**Решение**: server-side POST `{baseUrl}/chat/completions` с Bearer API key, JSON body, model из
окружения, `response_format: {"type":"json_object"}`, `stream:false`, ограниченным `max_tokens` и
AbortSignal timeout.

**Обоснование**: официальный контракт поддерживает JSON mode и Chat Completions без дополнительного
SDK. Промпт явно требует JSON, потому что это обязательное условие режима. Источник:
[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) и
[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/).

**Альтернативы**: OpenAI SDK добавляет зависимость без продуктовой пользы; свободный text сложнее
безопасно валидировать; browser fetch раскрывает ключ и запрещён конституцией.

## Роль AI

**Решение**: модель объясняет уже рассчитанные агрегаты и предлагает следующий проверяемый
эксперимент, но не выбирает протокол и не пишет наблюдения.

**Обоснование**: сохраняет воспроизводимость аналитики и даёт пользователю заметную AI-ценность.

**Альтернативы**: свободный чат повышает риск медицинских советов и стоимость; AI-назначение задач
делает исторические решения невоспроизводимыми.

## Минимальная выборка и fallback

**Решение**: внешний вызов после трёх полных сессий; при меньшей выборке — объяснение прогресса. При
ошибке — нейтральное «AI временно недоступен», при этом детерминированные метрики остаются.

**Обоснование**: одна-две сессии не дают устойчивого персонального паттерна; fallback обязателен по
конституции.

## Кэш

**Решение**: один `coach_insights` row на пользователя, keyed логическим fingerprint агрегированного
профиля.

**Обоснование**: одинаковая статистика не должна повторно тратить деньги или менять формулировку.

**Альтернативы**: in-memory cache теряется на Render restart; TTL без fingerprint возвращает
устаревший текст после новой сессии.

## Snooze

**Решение**: перенести существующий `nextTriggerAt` на пять минут, не меняя localTime/timezone.

**Обоснование**: cron уже атомарно резервирует этот момент, а следующий daily trigger вычисляется
из сохранённого локального времени.

**Альтернативы**: browser timer перестаёт работать после закрытия Mini App; отдельная очередь и
таблица избыточны для одного snooze.
