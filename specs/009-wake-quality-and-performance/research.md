# Исследование решений

## Проверка шагов

**Решение**: оставить честную самопроверку и добавить обязательный 20-секундный интервал.

**Обоснование**: Telegram WebView не гарантирует единый шагомер на iOS и Android. Таймер устраняет мгновенное формальное завершение, не создавая ложного заявления о датчиковой проверке.

**Альтернативы**: accelerometer недостаточно точно отличает ходьбу от движения телефона; камера требует отдельного privacy/consent этапа; wearable увеличивает интеграционный scope.

## Адаптация когнитивной сложности

**Решение**: ограниченная адаптация внутри задания, три правильных ответа для математики и два раунда памяти.

**Обоснование**: пользователь сразу получает подходящую нагрузку, а исторические эксперименты не меняют смысл без отдельной модели межсессионной сложности.

**Альтернативы**: самооценка уровня создаёт лишний вопрос; глобальный skill score требует новой экспериментальной гипотезы и защиты от смешения эффекта сложности с эффектом протокола.

## Динамика по дням

**Решение**: среднее парное изменение всех типов пробуждения по локальной дате с раскрытием контекста отдельных сессий.

**Обоснование**: общий график отвечает на вопрос о результате приложения после любого сна, а контекст остаётся виден и продолжает разделять экспериментальные сравнения.

**Альтернативы**: отдельные графики для каждого контекста будут пустыми при малой выборке; UTC-дни не совпадают с пользовательским восприятием даты; линия каждой сессии шумнее при нескольких запусках в день.

## AI-расходы

**Решение**: явный POST по кнопке, максимум один новый provider-анализ на локальный день, cache и deterministic fallback.

**Обоснование**: открытие экрана не означает согласие расходовать запрос, а серверный limit нельзя обойти повторным нажатием или другим устройством.

**Альтернативы**: client-only limit обходится; автоматическое обновление по fingerprint непредсказуемо по стоимости; rolling 24 hours менее понятно пользователю, чем следующий локальный день.

## Code splitting и зависимости

**Решение**: сначала удалить мёртвый Figma UI-kit, затем выделить settings, trend/help и уже существующие legal/admin области в lazy chunks.

**Обоснование**: это снижает install surface и initial parse без нового framework и без переписывания работающего wake-flow.

**Альтернативы**: ручные vendor chunks лишь меняют раскладку загрузки; полный rewrite App повышает риск; добавление новой component library увеличивает bundle.
