# Quickstart проверки

## Предварительные условия

- Node.js 22–24, pnpm 11.19.0, установленные зависимости;
- отдельная локальная/disposable PostgreSQL 17, не Neon/production;
- migrations применены штатной командой.

## Быстрые сценарии

1. Запустить domain tests и убедиться, что selector исследует разные допустимые варианты, затем
   проверяет лучший, не повторяя exact sequence подряд.
2. Запустить analytics fixture с 13 сессиями без готового factor effect: profile содержит общие
   наблюдения и comparison progress.
3. Запустить PostgreSQL integration fixture с первой/второй сессиями до, на и после границы 7 суток;
   вручную сверить cohort, eligible, returned и pending.
4. Запустить web component tests: статистика показывает профиль, `n`, confidence и точный progress;
   admin показывает новую пилотную карточку.
5. Выполнить `pnpm verify:release:full` только на disposable PostgreSQL, затем mobile E2E.

## Ожидаемый результат

- одинаковый input всегда даёт одинаковое назначение и объяснение;
- ограничения анкеты и бюджета соблюдены;
- одинаковая последовательность подряд возникает только при отсутствии альтернативы;
- D1/D7 не изменились;
- UI не делает причинных или медицинских утверждений и не скрывает размер выборки.
