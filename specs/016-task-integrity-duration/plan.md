# План: честные задания и длительность протокола

## Кратко

Добавить единую versioned policy успешного завершения когнитивных заданий, применять её в UI и
серверном переходе сессии, увеличить нагрузку 10-минутного режима и объяснить пользователю, что
контекст разделяет персональные эксперименты, а не гарантирует заранее другой протокол.

## Технический контекст

- TypeScript strict, React/Vite web, Fastify API, существующий `packages/domain`.
- Схема PostgreSQL и HTTP shape результата задания не меняются: используются `correct`, `total`,
  `durationMs`, версия протокола и сохранённый `durationMinutes` сессии.
- Новые назначения получают protocol version 3 и новые strategy versions; старые активные сессии
  сохраняют прежние правила для совместимого завершения.
- Никаких новых dependencies, provider, datastore, worker или production config.

## Constitution check

- **Надёжность**: синхронная блокировка реакции исключает double tap; старые checkpoints остаются
  завершаемыми.
- **Честность эксперимента**: правила зависят от versioned protocol identity, исходные попытки
  сохраняются, контексты не смешиваются.
- **Приватность**: новые данные и внешние вызовы отсутствуют.
- **Архитектура**: цели завершения определяет домен; UI отображает и исполняет их, API подтверждает
  переход через существующий repository boundary.
- **Проверяемость**: domain, component, contract и mobile E2E regressions обязательны.
- **Управление изменениями**: migration и production mutation отсутствуют; выпуск остаётся решением
  владельца после CI и Telegram smoke.

Все gates проходят без исключений до и после проектирования.

## Решения

### Единая policy нагрузки

Домен возвращает количество требуемых успешных раундов для task ID и бюджета. Для protocol version
3 сервер не принимает когнитивный результат ниже цели. UI использует ту же функцию, поэтому текст,
цикл задания и серверная проверка не расходятся.

### Обратная совместимость

Правило минимального числа успехов применяется только к новым protocol version 3. Это позволяет
возобновить назначенную ранее сессию. Новые strategy versions отделяют результаты изменённой
нагрузки в аналитике и admin breakdown.

### Десятиминутный режим

В 10 минутах математика, внимание и реакция требуют пять успехов, память — три. Безопасные timed
actions получают увеличенный интервал через существующую конфигурацию UI. Оценка длительности в
персонализаторе использует ту же градацию нагрузки, не возвращая исключённые задания.

### Контекст

Контекст не вводит недоказанные пресеты. Он сохраняется на сессии, ограничивает evidence selector и
объясняется рядом с выбором: одинаковое первое назначение допустимо, последующая рекомендация
обучается отдельно для каждого контекста и бюджета.

## Точки изменения

- `packages/domain/src/task-policy.ts`, `session/session.ts`, `experiments/learning.ts`,
  `personalization.ts` — policy, server validation, versioning и workload estimates.
- `apps/web/src/app/App.tsx` — честные циклы реакции, внимания, памяти и нагрузка по бюджету.
- `apps/web/src/features/personalization/wake-context-sheet.tsx` — объяснение роли контекста.
- `packages/domain/tests`, `apps/web/tests`, `apps/api/tests/contract`, `tests/e2e` — regressions.
- Архитектура, API-карта, testing, roadmap, release checklist и handoff — фактическое поведение.

## Failure modes и откат

- При недостаточном результате API возвращает существующий безопасный session conflict с canonical
  session; клиент не показывает успех и позволяет продолжить шаг.
- Double tap блокируется ref до React rerender; таймеры очищаются при unmount.
- Откат к предыдущему коду не требует отката schema. Назначения version 3 остаются читаемыми;
  предыдущий API примет их по прежней общей валидации результата.
- Главный release-риск — рассинхрон Static Site/API во время deploy; smoke проверяет один точный SHA.
