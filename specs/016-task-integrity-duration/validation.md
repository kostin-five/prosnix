# Validation: честные задания и длительность протокола

**Дата:** 9 сентября 2026 года
**Среда:** локальная; disposable PostgreSQL 17 на `127.0.0.1:55443`

## Автоматические проверки

- `pnpm verify:release` — пройден.
- `pnpm verify:release:full` — пройден после миграций с нуля на отдельной локальной базе.
- Domain: 39/39 тестов.
- Web component: 32/32 теста, включая regressions когнитивных заданий, единственного нового
  светового шага и legacy renderer.
- API: 83/83 теста в полном прогоне.
- PostgreSQL integration: 19/19 тестов.
- Mobile Chromium E2E: 17/17 сценариев.
- Production dependency audit: известных high-уязвимостей нет.
- Production boundaries: 13 файлов проверено, нарушений нет.
- Initial web bundle: 236,3 КиБ при лимите 240 КиБ.

Первый полный integration-прогон выявил старые fixtures с одной успешной попыткой и ожиданием
`adaptive-v2`. Fixtures переведены на versioned policy и `adaptive-v3`; повторный отдельный
integration-прогон и итоговый полный gate прошли.

Повторная ручная проверка выявила четыре результата реакции при подписи «Раунд 3 из 3», после чего
сервер вернул конфликт версии сессии. Это несовместимо с текущей целью в пять раундов для режима
10 минут и указывает на вероятное сочетание закэшированного старого frontend с новым API. Помимо
обновления protocol version добавлена общая single-flight защита отправки результата и
восстановление на каноническом шаге после конфликта.

Следующий smoke подтвердил систематическую остановку на первом длинном когнитивном шаге. Публичный
`index.html` на момент диагностики имел `Last-Modified: Tue, 08 Sep 2026 16:48:01 UTC`, тогда как API
уже возвращал семишаговый protocol v4. Это подтвердило смешанный rollout старого frontend и нового
API. Добавлены понятное сообщение для `invalid_transition`, E2E возврата на главную без закрытия
Mini App и PostgreSQL regression последовательного принятия всех семи шагов. Отдельно прошли web
32/32, PostgreSQL integration 19/19 и resume E2E 2/2.

Render Static Site deploy `c05a428` дополнительно подтвердил инфраструктурную причину старой
сборки: `pnpm --filter @awc/web build` запускал Vite без собранного entry `@awc/domain`. Web package
получил `prebuild` с явной сборкой domain; Render Build Command и архитектурные границы не меняются.

## Что подтверждено

- Преждевременные и повторные нажатия реакции не завершают раунд.
- Ошибка внимания не увеличивает число правильных ответов.
- Ошибка памяти запускает новую последовательность без продвижения.
- Режим 10 минут использует цели 5/5/5/3 для math/stroop/reaction/memory и увеличенные безопасные
  интервалы timed tasks.
- Полный профиль получает семь уникальных разрешённых шагов; если профиль разрешает меньше семи
  разных заданий, используются все доступные без запрещённых замен и дублей.
- Если в назначении есть приседания и разминка движением, ходьба или встряхивание располагаются до
  приседаний.
- Повторный или запоздалый callback одного шага не отправляется; после конфликта UI принимает
  канонический шаг сервера и разрешает продолжить.
- Backend последовательно принимает baseline, все семь корректных результатов protocol v4 и
  итоговую оценку на реальной PostgreSQL.
- Новые protocol v5 не назначают отдельный `curtains`, используют один `window` («Яркий свет») и
  сохраняют семь уникальных шагов при полном профиле; legacy `curtains` остаётся отображаемым и
  завершаемым.
- Кнопка «Закрыть» отменяет сохранённую сессию и возвращает на главную внутри Mini App.
- Backend отклоняет недостаточный результат protocol version 3 и принимает достаточный.
- Ранее назначенные protocol versions 1–2 сохраняют старый контракт завершения.
- Evidence разных контекстов не смешивается; одинаковое стартовое назначение без собственных данных
  контекста допустимо и объяснено в UI.

## Не проверено автоматически

- Реальная субъективная длительность режима 10 минут внутри Telegram на iOS/Desktop.
- Полное закрытие и повторное открытие Mini App после deploy точного SHA, чтобы исключить старый
  frontend из кэша Telegram.
- Telegram Android WebView — устройства у владельца нет.
- Production deploy, Neon, webhook, cron, DeepSeek и billing не затрагивались.

## Остаточные риски

- Бюджет — целевой уровень нагрузки, а не обещание точного десятиминутного секундомера: скорость
  ответов пользователя меняет фактическую длительность.
- Initial bundle имеет запас около 3,6 КиБ до установленного лимита.
- После выпуска нужен ручной smoke старой активной сессии и нового режима 10 минут на точном SHA.
- API и Static Site должны выпускаться из одного SHA; зелёный API deploy сам по себе не обновляет
  отдельный Render Static Site.

## Дополнение: protocol version 6

Ручной технический прогон выявил четыре одинаковые фактические последовательности подряд во время
первых семи сессий. Причина была не в случайности: learning-каталог чередовал две почти одинаковые
заготовки, а фильтрация возможностей и обязательное активное задание превращали их в одну и ту же
последовательность. Предыдущий regression проверял только отсутствие немедленного повтора среди
adaptive-кандидатов после калибровки и не проверял семь фактических назначений после
персонализации.

Для protocol version 6 добавлены семь разных калибровочных порядков и regression полного и
ограниченного профиля. Карточка «Следующий эксперимент» во время калибровки больше не показывает
лучшую историческую последовательность как будто она уже назначена. Реакция теперь засчитывается
только при результате строго быстрее 500 мс; 500 мс и более остаются попытками того же раунда.

Локально после изменения подтверждено:

- typecheck пяти workspace-пакетов — пройден;
- domain unit — 40/40;
- API unit/contract — 68/68, ещё 15 DB-зависимых тестов ожидаемо пропущены без test database;
- web component — 33/33;
- production build contracts/domain/db/API/web — пройден;
- production boundaries — 13 файлов, нарушений нет;
- initial web bundle — 238,3 КБ при лимите 240 КБ;
- форматирование затронутых файлов и `git diff --check` — пройдены.

Команда `pnpm verify:release` не дошла до проверок: pnpm потребовал интерактивного подтверждения
пересоздания `node_modules` из-за конфигурации store (`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`).
Рабочие зависимости не удалялись; эквивалентные доступные стадии выполнены напрямую. Полный gate с
PostgreSQL, audit и Playwright, CI и deploy точного SHA остаются обязательными перед пилотом.
