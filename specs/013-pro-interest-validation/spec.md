# Спецификация: Проверка интереса к Pro 0.4

**Создано**: 7 сентября 2026 года
**Статус**: Утверждено к реализации

## Контекст

До решения владельца о монетизации Prosnix должен проверить интерес к одной возможной ценности Pro без
цены, checkout, списаний, Telegram Stars или изменения существующего wake flow. Исследование не
является обещанием подписки: пользователь видит это явно.

## Пользовательские сценарии

### История 1 — Выразить интерес без оплаты (P1)

Пользователь с достаточным опытом завершённых пробуждений видит в статистике необязательное
предложение будущего расширенного режима, понимает, что денег не спишут, и одним действием оставляет
намерение.

**Почему P1**: это минимальная проверка ценности до добавления платёжного пути.

**Независимая проверка**: пользователь с семью completed sessions открывает статистику, выбирает один
из ответов и после обновления не видит повторный вопрос.

**Сценарии приёмки**:

1. **Дано** не менее семи completed sessions, **когда** пользователь открывает статистику, **тогда**
   он видит карточку с пометкой «это не подписка» и без цены либо платёжной кнопки.
2. **Дано** доступная карточка, **когда** пользователь выбирает «Интересно», «Пока не нужно» или
   «Неинтересно», **тогда** сервер сохраняет ровно один ответ текущей версии исследования.
3. **Дано** уже сохранённый ответ, **когда** пользователь заново открывает приложение, **тогда**
   карточка не предлагает ответить повторно.

### История 2 — Понять предполагаемую ценность (P2)

Пользователь, выбравший интерес, отмечает, что ему ближе: длинная история, более глубокие
эксперименты или оба направления. Это не меняет рекомендации, доступ и исходные метрики.

**Независимая проверка**: выбор интереса требует ровно одного уточнения ценности и хранится вместе с
намерением.

### История 3 — Видеть только агрегаты в admin (P2)

Администратор видит суммарное число ответов, распределение намерений и интересов, но не может
просмотреть или сопоставить отдельный ответ с пользователем.

**Независимая проверка**: admin summary возвращает только счётчики, а не user ID или ответы по людям.

## Крайние случаи

- При менее чем семи completed sessions, ошибке сети или временной недоступности API карточка не
  блокирует статистику и wake flow.
- Повторная отправка из-за повтора сети не создаёт второй ответ и возвращает актуальный status.
- Для «Пока не нужно» и «Неинтересно» не требуется уточнение ценности.
- Удаление профиля удаляет и ответ исследования вместе с пользовательскими данными.

## Требования

- **FR-001**: Система MUST показывать исследовательскую карточку только авторизованному владельцу
  профиля после семи completed sessions и только в статистике.
- **FR-002**: Карточка MUST честно сообщать, что это не подписка и что оплата, цена, checkout и
  Telegram Stars отсутствуют.
- **FR-003**: Сервер MUST принимать одно идемпотентное намерение на пользователя и версию исследования:
  `interested`, `not_now` или `not_interested`.
- **FR-004**: Для `interested` сервер MUST требовать один интерес: `long_history`,
  `deeper_experiments` или `both`; для остальных намерений интерес не сохраняется.
- **FR-005**: Новая запись MUST быть серверно авторизована, храниться в PostgreSQL через repository,
  удаляться каскадом с профилем и не менять назначение, аналитические формулы, платежи или доступ.
- **FR-006**: Admin summary MUST возвращать только агрегированные счётчики ответов и интересов без
  пользовательских идентификаторов и без нового персонального admin endpoint.
- **FR-007**: Повторный запрос и недоступность карточки MUST иметь безопасную неблокирующую деградацию.
- **FR-008**: Миграция MUST быть новой, forward-only и покрытой отдельным PostgreSQL integration test.

## Сущности

- **Pro interest response**: один ответ владельца для versioned research offer; содержит намерение,
  необязательный интерес для положительного намерения и server timestamp.
- **Pro interest aggregate**: admin-only счётчики по намерению и интересу без данных отдельных людей.

## Критерии успеха

- **SC-001**: Пользователь с семью completed sessions может оставить ровно один ответ без доступа к
  платёжному пути.
- **SC-002**: Повторная отправка не создаёт дубликат и возвращает уже сохранённый статус.
- **SC-003**: Admin response содержит семь агрегированных счётчиков и не содержит `userId`.
- **SC-004**: Ошибка загрузки или отправки не делает статистику или wake flow недоступными.

## Уточнения

### Сессия 2026-09-07

- Порог выбран равным семи completed sessions: это совпадает с порогом готовности общего профиля и
  исключает вопрос до появления личного опыта.
- Проверяется только интерес, а не willingness-to-pay по цене: ценность и условия оплаты остаются
  решением владельца после интервью.
- Версия предложения — `pro-interest-v1`; изменение текста или вариантов в будущем требует новой
  versioned research offer, а не перезаписи ответа.

## Границы и допущения

- Используется действующая Telegram server authentication и модульный монолит.
- Нет интеграции Telegram Stars, billing, checkout, цены, подписки, уведомлений или production mutation.
- Текущий feedback `0.3` остаётся независимым: оба исследования могут появиться в статистике, но ни
  одно не блокирует другое.
