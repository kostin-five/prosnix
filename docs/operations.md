# Эксплуатация Adaptive Wake Coach

Эта инструкция предназначена для staging и будущего production. Она не заменяет
[первоначальную настройку Telegram Mini App](./telegram-mini-app-setup.md), а описывает ежедневную
проверку, deploy, диагностику и безопасный откат.

## 1. Где что находится

| Компонент   | Где управлять                | Что хранится                                        |
| ----------- | ---------------------------- | --------------------------------------------------- |
| Код и CI    | GitHub, ветки `dev`/`master` | исходники, workflow, без секретов                   |
| API         | Render Web Service           | серверные Environment variables                     |
| Web         | Render Static Site           | собранный React; секретов нет                       |
| База        | Neon                         | пользователи, сессии, расписания, AI cache          |
| Бот         | BotFather                    | токен выдаётся один раз, хранится в Render API      |
| Планировщик | cron-job.org                 | dispatch URL и `CRON_SECRET` в Authorization header |

## 2. Перед deploy

1. Убедитесь, что рабочая ветка `dev` и `git status` не содержит случайных файлов.
2. Запустите PostgreSQL и полный набор:

   ```bash
   pnpm db:start
   pnpm db:migrate
   pnpm verify:release:full
   pnpm db:stop
   ```

3. Проверьте, что `pnpm audit --prod --audit-level high` не показывает high/critical.
4. Отправьте commit в `origin/dev` и дождитесь зелёных GitHub Actions.
5. Убедитесь, что Render начал deploy именно нового SHA.

## 3. Порядок deploy

1. Render API выполняет `pnpm install --frozen-lockfile`, build и forward-only миграции.
2. Новый API стартует и отвечает на `/ready` только после успешного подключения к БД.
3. Render переключает трафик и посылает старому процессу SIGTERM; API закрывает соединения не более
   чем за заданный deadline.
4. Static Site публикуется после успешной сборки и продолжает проксировать `/api/*`, `/health` и
   `/ready` к API.

Рекомендуемый Render Health Check Path: `/ready`. `/health` подтверждает только живой Node.js
процесс и не гарантирует доступность PostgreSQL.

## 4. Smoke-test после deploy

Проверьте публичные адреса:

```bash
curl --fail --silent https://wake-coach.onrender.com/health
curl --fail --silent https://wake-coach.onrender.com/ready
curl --fail --silent https://wake-coach-1.onrender.com/ready
```

Затем в Telegram:

1. Откройте `@wake_coach_bot` и Mini App.
2. Убедитесь, что главная загрузилась без повторной авторизации.
3. Начните сессию, подтвердите один шаг, закройте и снова откройте Mini App.
4. Продолжите с правильного шага и завершите протокол.
5. Откройте статистику и раскройте последнюю запись истории.
6. Проверьте расписание и однократный snooze.
7. Для отдельной тестовой сессии дождитесь одного follow-up через 15–20 минут.

## 5. Backup и восстановление Neon

- Включите доступные point-in-time restore/backup возможности тарифа Neon.
- Перед рискованной миграцией создайте отдельную ветку/restore point базы.
- Не проверяйте восстановление поверх staging. Восстановите backup в отдельную временную базу,
  примените read-only проверки количества таблиц и тестовый API, затем удалите только временную БД.
- Строку восстановленной базы не публикуйте в GitHub Actions artifacts или чате.

Минимальная ежемесячная проверка: создать отдельное восстановление, применить текущие миграции,
запустить integration tests и записать дату/результат без пользовательских данных.

## 5.1. Как владельцу открыть `/admin`

1. В Render API Environment убедитесь, что `ADMIN_TELEGRAM_USER_IDS` содержит ваш числовой Telegram
   ID, а не username. Не публикуйте ID вместе с другими данными аккаунта.
2. Сначала откройте Mini App из `@prosnix_bot`, чтобы Telegram auth создал защищённую cookie.
3. В том же Telegram-клиенте отправьте себе в «Избранное» ссылку
   `https://wake-coach-1.onrender.com/admin` и откройте её.
4. Переключите периоды 7/30/90 дней. Панель должна показывать только агрегаты без Telegram ID,
   session UUID и индивидуальных оценок.
5. Если отображается «Админ-панель закрыта», проверьте allowlist и снова запустите Mini App из
   нужного бота. Обычный пользователь должен всегда получать этот закрытый ответ.

Для продуктового анализа передавайте только итоговые числа или обрезанный скриншот агрегатов. Не
передавайте cookie, `initData`, ID, свободные ответы или Render Environment.

## 6. Диагностика

### `/health` работает, `/ready` возвращает 503

1. Откройте Render logs по `requestId` и событию `readiness_failed`.
2. Проверьте наличие `DATABASE_URL`, статус Neon и лимит соединений.
3. Не вставляйте строку подключения в чат или issue.
4. После исправления дождитесь `200 {"status":"ready"}` до теста Telegram.

### Mini App открывается, API отвечает 401

1. Убедитесь, что приложение открыто кнопкой бота, а не обычной ссылкой браузера.
2. Сверьте токен именно этого бота в Render API.
3. Проверьте время сервера и `TELEGRAM_AUTH_MAX_AGE_SECONDS`.
4. Никогда не копируйте реальный `initData` в публичный лог.

### 429 `rate_limit_exceeded`

Подождите минуту и повторите один раз. Если это происходит при обычном использовании, проверьте
число экземпляров и прокси-заголовки Render. Меняйте `AUTH_RATE_LIMIT_MAX` или
`COACH_RATE_LIMIT_MAX` только по логам; при горизонтальном масштабировании нужен общий limiter.

### Cron отвечает 401/415/409

- 401: не совпадает `CRON_SECRET` в Render и заголовке cron-job.org;
- 415: отсутствует `Content-Type: application/json` или тело `{}`;
- 409: предыдущий dispatch ещё выполняется; дождитесь следующего окна, не создавайте второй cron.

## 7. Безопасный rollback

1. В Render выберите последний известный рабочий deploy того же сервиса.
2. Не откатывайте PostgreSQL-миграции и не удаляйте таблицы. Forward-only схема должна оставаться
   совместимой с предыдущим приложением.
3. После rollback проверьте `/health`, `/ready`, Telegram bootstrap и одну тестовую сессию.
4. Если проблема только в Static Site, откатывайте web независимо от API.
5. Зафиксируйте SHA, время, симптом и результат без токенов и пользовательских ответов.

## 8. Регулярные действия

- ежедневно: внешний monitor `/ready` и ошибки Render;
- еженедельно: просмотреть Dependabot PR и пропустить их через CI;
- ежемесячно: тест восстановления Neon и полный Telegram smoke на iOS/Android/Desktop;
- перед публичным релизом: отдельные production-бот, база, сервисы, секреты и юридические реквизиты.
