## Проверки

- `pnpm verify:release:full`: успешно; **245 unit/contract, 27 PostgreSQL integration, 32 mobile e2e**.
- `pnpm test:demo`: отдельная собранная версия успешно проходит проверку без API и внешних запросов.
- `pnpm audit --audit-level high`: ноль известных уязвимостей, включая dev-пакеты.
- Gitleaks: история 98 commits и подготовленная копия текущих исходников — без подтверждённых секретов.
  Реальные `.env` не читались и не копировались. Единственное исключение — точный fingerprint
  исторического синтетического idempotency key; текущий fixture переименован в короткий понятный ключ.
- Production boundaries: синтетическая история и известные секретные значения не попадают в обычный web bundle.
- Generated migration snapshots и lockfile не редактировались вручную для уменьшения числа строк.

Эти результаты относятся к локальному дереву. CI точного будущего commit ещё не подтверждён.
Проверки не доказывают отсутствие любых уязвимостей и не заменяют внешнюю ревизию.

## Перед сменой видимости GitHub

1. **Лицензия согласована:** MIT для кода и собственных материалов, включая логотип. Сторонние
   лицензии сохраняются; происхождение исторических сторонних ресурсов требует проверки.
2. **Проверить историю персональных и посторонних материалов.** Школьные презентации убраны из
   текущего дерева и сохранены в `Desktop/prosnix-private-archive/2026-10-06/presentations`, но их
   старая история остаётся в Git. В истории также могут быть прежние ФИО оператора и авторы commits.
   Владелец выбрал текущий репозиторий с сохранением истории. Её переписывание не разрешено;
   проверка исторических материалов остаётся необходимой перед сменой публичности.
3. Проверить право публиковать логотип, иллюстрации и все бинарные материалы. Secret scan не выполняет
   полную OCR/визуальную проверку каждого исторического изображения и видео.
4. Закоммитить согласованное дерево, проверить все три CI jobs на точном SHA, затем менять видимость.
   Черновики `docs/design`, `assets/previews`, `assets/gemini/amber-protocol-preview` не включены в этап.
5. При желании разместить **только `dist-demo`**, без server env, БД, токенов и API rewrite. Для
   работающей Telegram-версии отдельно проверить документы оператора, webhook и внешний smoke-test.
6. Настроить приватный канал сообщений об уязвимостях; GitHub private vulnerability reporting
   включается владельцем отдельно.

Production, настройки GitHub, webhook, платежи и ключи не изменены. Оснований утверждать, что реальные
ключи утекли, аудит не обнаружил. Если владелец знает о прежней публикации ключа вне этого дерева,
его нужно отозвать независимо от результатов проверки.

## Оценка как портфолио

**Junior+ / начальный Middle по инженерной сложности.** Сильные стороны: цельный работающий сценарий,
серверные границы, транзакции, идемпотентность, восстановление, адаптеры интеграций и несколько уровней
проверок. Рефакторинг и security gate делают эти решения более убедительными для демонстрации.

До уверенного Middle: самостоятельное объяснение компромиссов, диагностика реальных отказов,
нагрузочные измерения и эксплуатация. Размер проекта и число документов сами по себе грейд не
определяют. Senior-уровень этим репозиторием подтвердить нельзя. Личный грейд автора оценивается по
тому, насколько он самостоятельно понимает, изменяет и отлаживает реализацию.
