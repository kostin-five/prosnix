# Тестирование Prosnix

Тесты проверяют подлинность данных Telegram, переходы сессий, исходные наблюдения,
формулы аналитики, уведомления, принятие документов и платежи.
Количество тестов само по себе не подтверждает готовность приложения.

## Подготовка

Нужны Node.js 22–24, pnpm 11.19.0 и установленные зависимости.
Для интеграционных тестов используется отдельная локальная PostgreSQL 17 с применёнными миграциями.
В имени БД должно быть `test`. Рабочие и удалённые БД отклоняются до запуска тестов.
Имя базы — дополнительная проверка, а не гарантия: не направляйте рабочее подключение через localhost.

Для браузерных тестов установите Chromium:

```bash
pnpm exec playwright install chromium
```

## Уровни проверок

| Уровень              | Каталог                                            | Что проверяется                                             |
| -------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| Домен                | `packages/domain/tests`                            | Переходы состояний, подбор, аналитика и часовые пояса       |
| Контракты API        | `apps/api/tests/contract`                          | Доступ, схемы, коды, заголовки и ограничения запросов       |
| Адаптеры             | `apps/api/tests/coach`, `notifications`, `runtime` | DeepSeek, Telegram, отправка и завершение процесса          |
| Интеграция с БД      | `apps/api/tests/integration`                       | Миграции, транзакции, ограничения и каскадное удаление      |
| Компоненты           | `apps/web/tests`                                   | Задания, настройки, правовые страницы, панель и доступность |
| Сквозные сценарии    | `tests/e2e`                                        | Основной путь пользователя в мобильном Chromium             |
| Статические проверки | `scripts/verify-*`                                 | Размер сборки и отсутствие серверных секретов в клиенте     |

Обычная команда API `test` не включает интеграционные файлы. Они запускаются отдельно
и последовательно: сценарии уведомлений используют общую тестовую очередь.
Специальные проверки конкурентных запросов сохраняют параллельность внутри своего сценария.

## Команды

Быстрые проверки:

```bash
pnpm format:check
pnpm typecheck
pnpm test
```

Сборка и её границы:

```bash
pnpm build
pnpm verify:web-bundle
pnpm verify:production
pnpm audit --prod --audit-level high
```

Перед обычным слиянием:

```bash
pnpm verify:release
```

При изменении API, БД или выпуска — полный набор с подготовленной тестовой БД:

```bash
pnpm verify:release:full
```

Отдельные браузерные проверки:

```bash
pnpm test:e2e
pnpm test:demo
```

## Одноразовая тестовая БД

Все значения ниже — локальные тестовые данные. Файл `.env` для этого запуска не загружается.

```bash
docker run --rm -d --name prosnix-integration-test   -e POSTGRES_DB=prosnix_test -e POSTGRES_USER=fixture -e POSTGRES_PASSWORD=fixture   -p 127.0.0.1:55438:5432 postgres:17-alpine
# Дождитесь готовности БД: docker exec prosnix-integration-test pg_isready -U fixture
cd packages/db
DATABASE_URL='postgres://fixture:fixture@127.0.0.1:55438/prosnix_test' node node_modules/drizzle-kit/bin.cjs migrate
cd ../..
DATABASE_URL='postgres://fixture:fixture@127.0.0.1:55438/prosnix_test' pnpm verify:release:full
pnpm test:demo
docker stop prosnix-integration-test
```

Миграции проверяются с нуля и повторным запуском. Применённые SQL-файлы не редактируются ради теста:
нужно добавить следующую миграцию. Обычный `pnpm db:migrate` предназначен для своей
локальной разработки с заранее проверенной конфигурацией.

## Правила добавления тестов

Исправление ошибки должно проверять случай, в котором она возникала, на самом простом
достаточном уровне. Новая формула получает фиксированные входные данные и вручную рассчитанный
результат. Не закрепляйте внутреннюю реализацию, если достаточно проверить поведение.

### Сессии и данные

- Для записи API проверяйте отсутствие ключа операции, повтор, другой запрос с тем же ключом
  и конфликт `If-Match`.
- Для персональных данных — изоляцию двух пользователей и каскадное удаление профиля.
- Для отправки результата шага — защиту от двойного и запоздалого нажатия. После конфликта
  разрешена повторная попытка с актуальным серверным состоянием.
- Продолжение использует назначенные шаги и цели сохранённой версии; обновление каталога
  не переписывает активную сессию.
- Досрочное завершение сохраняет только выполненные задания и итоговую оценку,
  не создаёт вымышленные наблюдения и не входит в аналитику полных протоколов.
- Настройка паузы проверяется на 5/10/20 секунд, сохранение, изоляцию пользователей
  и остановку при скрытии окна. Кнопка «Проснулся» доступна слева от крестика на ширине 320 пикселей.

### Подбор и задания

- Подбор детерминирован, разделяет контексты сна и время, изучает альтернативы,
  повторно проверяет лучший вариант и избегает точного предыдущего порядка при наличии замены.
- Первые семь сопоставимых назначений полного профиля проверяются на разнообразие;
  ограниченный профиль не получает запрещённые действия ради заполнения времени.
- Версии 8 и выше проверяются по допустимому времени, а не только числу шагов.
  Недостаток разрешённых упражнений даёт `limited_eligible_tasks`.
- Новые пятиминутные назначения версии 10 имеют 6–7 шагов и план 270–330 секунд при полном профиле.
  Цели: четыре успешных когнитивных раунда, для памяти — три. Версии 8/9 продолжаются по старым правилам.
- Для 10 минут проверяются увеличенные цели и интервалы. Интеграционный сценарий последовательно
  отправляет все результаты с актуальной версией и завершает сессию.
- `sit_edge` появляется перед первым стоячим или физическим действием, а не перед каждым шагом.
- Новое назначение содержит один световой шаг `window`; старый `curtains` остаётся завершаемым.
- Старый профиль не получает умывание и отжимания без разрешений. Умывание нельзя подтвердить
  раньше 20 секунд, отжимания — раньше 25; им предшествуют подъём и разминка.
- Ошибки внимания и памяти не продвигают задание. Реакция принимает одно нажатие после сигнала;
  499 мс засчитываются, 500 мс — нет.

### Замена и дополнительный раунд

- Проверяйте текущий и следующий шаг, безопасный порядок, время, исключения профиля,
  выполненные и ранее отклонённые задания.
- Повтор замены защищён ключом операции. Исходное назначение не меняется,
  события только добавляются; начальная загрузка возвращает фактические `effectiveSteps`.
- Дополнительный раунд после `+1` содержит не более двух действий и 90 секунд.
  Его исходная оценка происходит из сохранённого результата основной сессии.
- Отказ сохраняется; принятие не создаёт повторов. История связывает обе сессии,
  основная статистика их не смешивает. Повторная проверка остаётся одна.
- Браузерные сценарии проверяют замену с причиной и восстановление дополнительного раунда.

### Аналитика и отчёт

- Проверяйте формулы из парных оценок, группировку по локальным датам, размер выборки
  и отсутствие причинных выводов из смешанного протокола.
- Порядок показывается после двух повторов в одинаковом контексте и времени.
  Проверяйте настройку отключения, число сопоставимых пар и состав данных для ИИ.
- Профиль после семи сессий не скрывается из-за нехватки пар факторов.
- Статистика показывает следующий шаг при 0, 1–6 и 7+ завершениях;
  во время загрузки нет ложного прогресса 0/7.
- До трёх завершений отчёт недоступен даже с `confirmEarly: true`, кэш и модель не вызываются.
  После третьего отчёт создаётся по нажатию, с проверкой кэша и дневного ограничения.
- Внешние адаптеры проверяются на превышение времени ожидания, некорректный ответ,
  повтор и базовый отчёт при сбое.
- Возврат ко второй сессии проверяется на границе семи суток; ожидающие пользователи
  считаются отдельно.

### Уведомления и режим без телефона

- Ответ в Telegram проверяется для `up`, `back`, `drowsy`: секрет, владелец, чат,
  запись доставки, повторное нажатие и сохранение через прежнюю команду.
- Режим без телефона назначает разрешённые неэкранные действия, сохраняет `completionSource`
  и отклоняет слишком ранний результат или таймер в обычном режиме.
- Пауза и скрытие окна останавливают подготовку. Следующий шаг открывается после ответа сервера;
  при отсутствии голоса остаётся экранный путь.
- Для версии 12 длительности `notice_three` и `find_color` равны 15 и 25 секундам;
  версия 11 сохраняет прежние интервалы. Значок паузы виден.
- Без действия пользователя звук не запускается. После включения повторяется до выключения
  или завершения; ошибка звукового API не прерывает задания.

### Интерфейс

- Первичная анкета — отдельные страницы; сохранение на последнем шаге.
- Предложение добавить приложение на главный экран вызывается после действия пользователя,
  не мешает неподдерживаемому клиенту и не повторяется на устройстве.
- Цель сохраняется явно, допускает пропуск и удаляется с профилем. Старый локальный текст
  не отправляется на сервер сам. Серверная цель проверяется на доступ и версию.
- Вечернее предложение первых трёх сессий не создаёт второго утреннего уведомления.
- Кнопки протокола и звука выровнены. Таймер имеет одно кольцо, приседания показывают две позы,
  при уменьшении движения — статичную. Основная кнопка доступна на мобильном экране.
- Профиль не дублирует показатели и объясняет степень уверенности обычным языком.
- Итог использует общий серверный счётчик и не начинает обучение заново.
- Закрытие сохранённой сессии возвращает на главную без закрытия мини-приложения.

## GitHub Actions

Проверки запускаются для запросов на слияние и отправки в `master` и `dev`:

- `verify`: PostgreSQL, установка, форматирование, типы, миграции, тесты,
  сборка, её границы, мобильные сквозные сценарии и демо;
- `security`: проверка зависимостей, включая инструменты разработки;
- `secrets`: поиск секретов в истории и текущих отслеживаемых файлах.

Новая отправка отменяет устаревшую проверку той же ветки. При ошибке браузерных тестов
сохраняются отчёт и трассировки Playwright. Обязательные проверки должны пройти до слияния;
локальный успех не заменяет результат для точного SHA на GitHub.

## Ручная проверка

На Telegram для iOS, Android и компьютера проверьте вход, документы, анкету,
запуск, продолжение после закрытия, завершение, расписание, откладывание и ответ через 15 минут.
Дополнительно — режимы 2/5/10 минут, ограничения упражнений, замену, дополнительный раунд,
ранний выход, историю, профиль, отчёт, цель и удаление тестового профиля.

Проверьте звук, системную громкость и возобновление после возврата.
Не обещайте работу голоса или звука при закрытом приложении и блокировке устройства.
Панель администратора проверяется разрешённым и обычным пользователем.
При включении оплаты нужен отдельный тестовый сценарий счёта, продления, отмены и возврата.

Мобильный Chromium не заменяет Telegram WebView. Ручная проверка Android остаётся
отдельным неподтверждённым пунктом, пока результат не зафиксирован.

## Дополнительные ограничения

`verify:module-size` проверяет TS, TSX, JS, MJS и CSS в приложениях, пакетах, скриптах и тестах.
Сгенерированные миграции и файл фиксации зависимостей не разделяются вручную.
`test:demo` проверяет собранное демо, включая отсутствие запросов к API и сторонним сервисам.

Поиск секретов не заменяет просмотр изображений и внешних хранилищ.
Нельзя исключать из проверки целые тестовые каталоги или произвольные коммиты ради прохождения CI.
