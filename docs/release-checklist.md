# Проверки перед выпуском Prosnix

Отмечайте пункты для конкретного коммита и среды. Успех предыдущего выпуска
не переносит отметки на следующий.

## Объём изменений

- [ ] Согласованы сценарий, API, схема данных и внешние интеграции, которых касается изменение.
- [ ] Проверены границы модулей, безопасность и сохранность данных; новые решения отражены в ADR.
- [ ] Нет незапланированных изменений аналитики, правовых документов или платежей.
- [ ] Дорожная карта и затронутая документация обновлены.
- [ ] В изменениях нет секретов, реальных ответов, результатов сборки и случайных отладочных журналов.

## Автоматические проверки

- [ ] `pnpm install --frozen-lockfile` проходит.
- [ ] Чистая сборка `pnpm --filter @awc/web build` сама собирает `@awc/domain`.
- [ ] `pnpm verify:release` проходит.
- [ ] Интеграционные тесты проходят на отдельной локальной PostgreSQL 17.
- [ ] Проверка зависимостей не сообщает уязвимостей высокой или критической степени.
- [ ] Мобильные браузерные сценарии и автономное демо проверены; ошибки и трассировки изучены.
- [ ] Все проверки GitHub Actions прошли для точного SHA.

## База данных

- [ ] Добавлены только новые миграции; применённые файлы не изменялись.
- [ ] Вся цепочка проверена с нуля и повторным запуском.
- [ ] Исправляющая миграция `0009` проверена на старой схеме без `past_due` и остаётся идемпотентной.
- [ ] Предыдущая версия приложения совместима с новой схемой для отката кода.
- [ ] Проверены резервная копия, период восстановления и ответственный за рабочую миграцию.
- [ ] Владелец явно разрешил изменение рабочей БД.

## Конфигурация и секреты

- [ ] Секреты есть только в окружении серверного API.
- [ ] Статический сайт получает только публичные настройки `VITE_LEGAL_*`.
- [ ] Секреты сессий, планировщика, токен бота и секрет входящих событий не совпадают случайно.
- [ ] `ADMIN_TELEGRAM_USER_IDS` содержит числовые ID разрешённых пользователей или пуст.
- [ ] Проверкой готовности выбран `/ready`; `/health` используется только для процесса.
- [ ] HTTPS, защищённые cookie, `no-store`, ограничения запросов и завершение процесса не ослаблены.

## Правовые документы и платежи

- [ ] `/privacy` и `/terms` содержат фактические сведения об операторе и контакте.
- [ ] Политика указана в BotFather.
- [ ] При существенном изменении документов обновлены `LEGAL_*_VERSION`.
- [ ] Закрыты применимые вопросы обработки и передачи данных.
- [ ] `TELEGRAM_STARS_MONTHLY_PRICE=0`, если отдельный запуск оплаты не утверждён.
- [ ] При нулевой цене панель не читает необязательные платёжные таблицы.
- [ ] Перед включением оплаты подтверждена полная схема БД и проверены счёт, продление,
      отмена, поддержка и возврат в тестовой среде Telegram.

Это инженерный список, а не юридическое заключение.
Подробности — в [правовых проверках](legal-launch-checklist.md).

## Развёртывание

- [ ] Зафиксированы среда, ветка и полный SHA коммита.
- [ ] Владелец разрешил развёртывание и изменения внешних сервисов.
- [ ] Проверена резервная копия; миграция применяется до проверки нового API.
- [ ] API запускается без ошибок конфигурации и отвечает на `/ready`.
- [ ] Статический сайт собран из совместимого коммита; опубликованные ресурсы относятся к новой версии.
- [ ] `/api/*`, `/health` и `/ready` направлены на актуальный API.
- [ ] Планировщик и входящие события Telegram не переключаются до готовности API.

## Проверка в Telegram после выпуска

### Основной сценарий

- [ ] `/health` и `/ready` возвращают `200` с ожидаемыми телами.
- [ ] Вход из нужного бота, документы и анкета проходят.
- [ ] Сессия создаётся, сохраняется, продолжается после закрытия и завершается.
- [ ] Двойное нажатие результата отправляет одну операцию; конфликт возвращает актуальное состояние.
- [ ] Закрытие сохранённой сессии возвращает на главную, не закрывая приложение.
- [ ] Досрочный выход сохраняет итоговую оценку и реальные выполненные шаги.
- [ ] История и аналитика отражают результат без внутренних UUID в интерфейсе.
- [ ] Ежедневное напоминание, откладывание и повторная проверка не дублируются.
- [ ] Три ответа повторной проверки в Telegram сохраняются один раз;
      чужое нажатие отклоняется, без настроенного обработчика доступен переход в приложение.

### Назначения и задания

- [ ] Два последовательных запуска различаются при наличии допустимой альтернативы.
- [ ] Контекст и длительность разделяют обучение; совпадение первых протоколов объяснено калибровкой.
- [ ] При полном профиле первые семь обучающих сессий не повторяют фактический порядок.
- [ ] Пятиминутные назначения содержат 6–7 шагов и цели своей версии;
      старые активные сессии сохраняют прежние правила.
- [ ] Режим 10 минут использует увеличенные интервалы и цели; запрещённых заданий нет.
- [ ] `sit_edge` стоит перед первым физическим действием, разминка — перед интенсивным.
- [ ] Новые назначения имеют один шаг «Яркий свет»; прежние «Шторы» ещё можно завершить.
- [ ] Ошибки внимания и памяти не завершают шаг. Реакция принимает одно нажатие после сигнала:
      499 мс засчитываются, 500 мс — нет.
- [ ] Замена и расширенный каталог доступны при согласованных настройках клиента и сервера.
      Старые профили не получают новые упражнения без разрешения.
- [ ] Дополнительный раунд предлагается один раз после полного основного протокола с изменением
      не выше `+1`; максимум два действия и 90 секунд. Отказ не теряет основной результат.
- [ ] Продолжение дополнительного раунда восстанавливается отдельно; история связывает записи,
      основная метрика не смешивает их, повторная проверка одна.

### Режим без телефона и звук

- [ ] Первый и повторный шаг озвучиваются на iOS и Android; при отсутствии голоса доступен экран.
- [ ] Настройка паузы 5/10/20 секунд сохраняется для пользователя и устройства.
- [ ] Пауза и скрытие окна останавливают отсчёт и звук; выключение звука прекращает сигналы.
- [ ] Сервер отклоняет слишком ранний результат таймера и таймер в обычном режиме.
- [ ] Длительности сохранённых версий не меняются; новые задания наблюдения имеют 15 и 25 секунд.
- [ ] Звук запускается только после действия пользователя и прекращается при завершении.
      Проверены системная громкость и возврат в приложение.

### Интерфейс и статистика

- [ ] На ширине 320 пикселей логотип и счётчик не пересекаются.
- [ ] Задание, таймер и основная кнопка доступны без лишней прокрутки;
      увеличенный шрифт сохраняет возможность прокрутки.
- [ ] Кнопки протокола и звука выровнены, таймер имеет одно кольцо.
      При уменьшении движения анимации останавливаются.
- [ ] Личная цель сохраняется явно и видна в напоминании; пустая цель даёт нейтральный текст.
- [ ] Статистика показывает следующий шаг при 0, 1–6 и 7+ завершениях без временного ложного 0/7.
- [ ] Общий профиль после семи сессий объясняет эффект и устойчивость, показывает размер выборки
      и не выдаёт корреляцию за причину.
- [ ] Гипотезы о порядке появляются только при разрешающей настройке и двух сопоставимых повторах.
- [ ] Итог использует общий серверный счётчик и не начинает обучение заново.
- [ ] Открытие статистики не вызывает DeepSeek. До трёх сессий отчёт недоступен,
      затем вызывается по кнопке не чаще одного нового внешнего запроса за локальный день.
- [ ] Неудачный отчёт допускает новую попытку после полуночи при неизменных данных.
      Для диагностики есть безопасное событие `coach_provider_failed`, без тела ответа и секретов.
- [ ] Административная панель доступна только разрешённым пользователям, показывает проверенные
      агрегаты и безопасный код запроса при сбое.
- [ ] Правовые страницы доступны без входа; принятие сохраняется.
- [ ] Журналы не содержат секреты или ответы пользователей.

- [ ] Известна предыдущая рабочая версия сервиса Render.
- [ ] Откат затрагивает код, но не применённую схему БД.
- [ ] После отката повторены проверка готовности, вход и тестовая сессия.
- [ ] Отклонения и результаты зафиксированы без персональных данных.
- [ ] В описании выпуска указаны коммит, проверки и ограничения.
