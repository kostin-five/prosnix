# API-контракты Prosnix

Основной путь — `/api/v1` через адрес клиента. Внутренние маршруты находятся под `/internal`.
Реализованные маршруты описаны в `apps/api/src`, схемы — в `packages/contracts`.
Этот документ служит картой API, а не схемой OpenAPI; при расхождении нужно свериться с кодом.

## Общие правила

- Персональные маршруты требуют cookie `awc_session`, полученный после входа через Telegram.
- Ответы `/api`, `/internal`, `/health` и `/ready` имеют `Cache-Control: no-store`.
- Максимальный размер тела — 32 КиБ.
- Записи сессий требуют `Idempotency-Key` длиной 8–128 символов.
- Переход существующей сессии требует `If-Match: <positive-version>`.
- Непредвиденная ошибка возвращает безопасный код и `requestId`, без стека вызовов.

| Код   | Значение                                      |
| ----- | --------------------------------------------- |
| `400` | Неверное тело запроса или заголовок           |
| `401` | Нет авторизации                               |
| `404` | Нет ресурса или скрыт административный доступ |
| `409` | Конфликт версии или недопустимый переход      |
| `429` | Превышена частота запросов                    |
| `503` | Недоступна зависимость или функция            |

## Вход и профиль

| Метод  | Маршрут                 | Вход и результат                                                                    |
| ------ | ----------------------- | ----------------------------------------------------------------------------------- |
| POST   | `/api/v1/auth/telegram` | `{ initData }`: проверка подписи, установка cookie, `204`                           |

## Сессии пробуждения

| Метод | Маршрут                                          | Дополнительные требования                                           |
| ----- | ------------------------------------------------ | ------------------------------------------------------------------- |
| POST  | `/api/v1/sessions`                               | Часовой пояс, контекст сна, длительность, ключ повторяемой операции |
| PUT   | `/api/v1/sessions/:id/baseline`                  | Исходная оценка, ключ операции, `If-Match`                          |
| PUT   | `/api/v1/sessions/:id/steps/:index`              | Результат задания, ключ операции, `If-Match`                        |
| PUT   | `/api/v1/sessions/:id/steps/:index/substitution` | `{ reason }`, ключ операции, `If-Match`                             |
| PUT   | `/api/v1/sessions/:id/post-rating`               | Итоговая оценка, ключ операции, `If-Match`                          |
| POST  | `/api/v1/sessions/:id/recovery`                  | Начать дополнительный раунд; ключ операции, `If-Match`              |
| POST  | `/api/v1/sessions/:id/recovery/decline`          | Отказаться; ключ операции, `If-Match`                               |
| PUT   | `/api/v1/sessions/:id/follow-up`                 | `{ outcome }`, ключ операции                                        |
| POST  | `/api/v1/sessions/:id/abandon`                   | Закрыть сессию; ключ операции, `If-Match`                           |
| GET   | `/api/v1/sessions/history?limit=1..20`           | Последние завершённые сессии                                        |

Конфликт `409` возвращает код и актуальное серверное состояние сессии.
Повтор идентичной операции возвращает сохранённый результат; тот же ключ с другим телом отклоняется.

### Режим без телефона

Создание принимает необязательное `interactionMode: "manual" | "hands_free"`;
по умолчанию используется `manual`. Режим возвращается в снимке `experience`.
Для `hands_free` назначаются только допустимые задания без экранного ответа.

Запись шага может содержать `completionSource: "manual" | "timer"`.
При `timer` сервер проверяет режим, идентификатор задания, результат 1/1 и минимальную
длительность по серверным часам. Старые результаты читаются как `manual`.
Версия протокола 12 задаёт 15 секунд для `notice_three` и 25 для `find_color`;
версия 11 сохраняет прежние интервалы. Расчёт длительности учитывает версию назначения.

### Звук и замена

Запись исходной оценки принимает необязательный снимок
`experience: { soundMode: "on" | "off" }`. Это явный выбор пользователя, а не системная громкость.
Ответы сессии и начальной загрузки могут содержать `effectiveSteps`, `substitutions`,
`sessionKind`, `parentSessionId`, `recoveryBaseline`, `recoveryOffer`; старые клиенты могут их игнорировать.

При `WAKE_TASK_SUBSTITUTION_ENABLED=false` замена возвращает `404 feature_unavailable`.
Разрешённые причины — `unwilling_now`, `not_helpful`, `cannot_do`.
Сервер допускает замену текущего или следующего невыполненного шага и возвращает `effectiveSteps`.
Повторный ключ возвращает прежний ответ; устаревшая версия — `409` с актуальной сессией.

### Дополнительный раунд

При `WAKE_LOW_EFFECT_RECOVERY_ENABLED=false` соответствующие маршруты недоступны.
Полная основная сессия с изменением не выше `+1` может получить одно предложение продолжить.
Принятие создаёт отдельную сессию `sessionKind=recovery` максимум с двумя действиями
и плановым пределом 90 секунд. Исходная оценка берётся из итоговой оценки основной сессии
и не дублируется новым наблюдением. Отказ сохраняется.

После принятия повторная проверка основной сессии снимается и назначается после завершения
или прекращения дополнительного раунда. История возвращает `sessionKind` и `parentSessionId`.
Основная метрика `averageDelta` учитывает только основные сессии.

### Результаты и досрочное завершение

Для версии протокола 3 минимальные цели заданий: три успешных раунда математики, внимания
и реакции для 2/5 минут, пять — для 10 минут; памяти — два и три соответственно.
`total` включает ошибки и не может быть меньше `correct`. Недостаточный результат
возвращает `409 invalid_transition`, не продвигая шаг. Версии 1–2 читаются по прежним правилам;
последующие версии используют цели, сохранённые в назначении.

Итоговая оценка принимает `completionReason: "awakened"` для явного досрочного завершения
после исходной оценки. Без поля нужно выполнить все шаги. Невыполненным заданиям результаты
не создаются. Неполный порядок получает `experience.completedEarly: true`, а история —
`completedEarly`. Проверки принадлежности, версии, повторяемости и повторная проверка сохраняются.
Досрочная сессия исключается из обучения, аналитики полных протоколов и дополнительных раундов.
Запись хранится в существующем JSON-снимке; отдельная миграция не нужна.

## Аналитика и персональный отчёт

| Метод | Маршрут                     | Результат                                             |
| ----- | --------------------------- | ----------------------------------------------------- |
| GET   | `/api/v1/analytics/profile` | Метрики, степень уверенности и сведения о наблюдениях |
| POST  | `/api/v1/coach/insight`     | Ручной отчёт с кэшем или базовым расчётом             |

`dailyTrend` содержит среднее парное изменение по локальным датам, число сессий
и идентификаторы наблюдений. Разные контексты сна объединяются только в этом обзорном ряду.

Поле `confirmEarly` принимается для совместимости, но не обходит порог трёх завершённых сессий.
До порога отчёт возвращает `unavailable` и `insight: null` без чтения кэша или обращения к модели.
С третьей сессии допускается один новый внешний отчёт за локальный календарный день.
ИИ получает агрегаты, без исходных ответов, точного времени, Telegram ID и идентификаторов сессий.

Открытие статистики не вызывает модель. Явный запрос возвращает поля `source`, `limitReached`
и `refreshAvailableAt`. Перед ответом профиль пересчитывается. Если в тот же день появилась
новая сессия, свежие данные отражаются детерминированным расчётом без второго внешнего вызова.
Отчёт имеет отдельное ограничение частоты запросов и не меняет метрики и состояние сессии.

`analytics-v2` может возвращать `sequenceEffects`: наблюдаемый результат точного порядка заданий
с контекстом, длительностью, размером выборки `n` и степенью уверенности.
Он появляется после двух повторов в одинаковых условиях и не является причинным выводом.
При `WAKE_COMBINATION_ANALYTICS_ENABLED=false` профиль и отчёт возвращают пустой список этих гипотез.
Исходные наблюдения продолжают сохраняться.

`comparisonProgress` содержит для каждого фактора `withCount`, `withoutCount`, `pairCount`,
`targetPairs`, `status`. Готовность общего профиля после семи сессий не зависит от достижения
трёх пар. Разные контексты и длительности не смешиваются. Клиент поддерживает `analytics-v1`
для совместимого обновления.

## Обратная связь и интерес к Pro

| Метод | Маршрут                       | Назначение                                                 |
| ----- | ----------------------------- | ---------------------------------------------------------- |
| GET   | `/api/v1/experiment-feedback` | Доступность и факт единственного ответа                    |
| POST  | `/api/v1/experiment-feedback` | Оценки `helpful`, `irritating`, `continueIntent` от 1 до 5 |
| GET   | `/api/v1/pro-interest`        | Доступность исследования и факт ответа                     |
| POST  | `/api/v1/pro-interest`        | Намерение и интересующая возможность                       |

Все маршруты требуют сессию владельца. Обратная связь доступна после пяти завершений,
ограничена по частоте и не меняет назначения или оценки. Повтор возвращает сохранённый статус.

Исследование Pro доступно после семи завершений. Принимается `interested` с `long_history`,
`deeper_experiments` или `both`; для `not_now` и `not_interested` уточнение не требуется.
Здесь нет цены, счёта или изменения доступа. Ответ сохраняется один раз.

## Возможности, цель и распорядок

| Метод | Маршрут                        | Назначение                                       |
| ----- | ------------------------------ | ------------------------------------------------ |
| GET   | `/api/v1/me/wake-profile`      | Возможности и исключения                         |
| PUT   | `/api/v1/me/wake-profile`      | Изменение профиля; ключ операции, `If-Match`     |
| GET   | `/api/v1/me/life-goal`         | Сохранённая цель и версия                        |
| PUT   | `/api/v1/me/life-goal`         | Текст до 120 символов; ключ операции, `If-Match` |
| GET   | `/api/v1/me/wake-routine`      | Личный распорядок                                |
| PUT   | `/api/v1/me/wake-routine`      | До пяти пунктов; ключ операции, `If-Match`       |
| GET   | `/api/v1/sessions/:id/routine` | Выполнение распорядка конкретной сессии          |
| PUT   | `/api/v1/sessions/:id/routine` | Отметки пунктов; ключ операции, `If-Match`       |

Профиль исключает неподходящие задания. Контекст и длительность сохраняются в назначении.
Распорядок не участвует в аналитике. Текущий алгоритм описан в [подборе протокола](protocol-selection.md).
Сохранённые версии назначений не переписываются при обновлении алгоритма.

Цель доступна только владельцу. Сервер убирает лишние пробелы; пустой текст удаляет цель
из будущих уведомлений. Начальная версия — 0. Локальная цель не загружается автоматически.

Дыхание `breathing` добавлено в версии 14: 30 секунд для всех длительностей и режима без телефона.
Более старые протоколы не получают его при замене. Для отжиманий нужны полный уровень движения,
`active_movement` и `floor_space`; нажатие карточки упражнения не подтверждает свободное место.

## Административная панель

`GET /api/v1/admin/growth` требует авторизации Telegram и серверного разрешения.
Остальным возвращается `404`. Параметр `days` принимает `7`, `30`, `90`; по умолчанию — `7`.
Ответ содержит сводки активности, воронки, парного изменения оценок, повторных проверок,
возвратов, назначений, анкет, распорядков, отчётов, доставок и платежей.

В `secondSessionWithin7Days` отдельно считаются `cohort`, `eligible`, `returned`, `pending`
и доля возврата. Пользователи, у которых ещё не прошло семь дней, не ухудшают показатель.
Доли при нулевом знаменателе равны нулю. Сессии отбираются по времени создания
в полуинтервале `[from, to)`; события после `to` не учитываются.

Индивидуальные оценки, Telegram ID и UUID пользователей или сессий не возвращаются.
Ошибка содержит только безопасный код и `requestId` для диагностики.
При выключенных продажах платёжные агрегаты равны нулю без чтения необязательных таблиц.
Совместимое чтение `status::text` не позволяет отсутствующему `past_due` обрушить панель.

## Платежи и входящие события Telegram

| Метод | Маршрут                      | Назначение                                                |
| ----- | ---------------------------- | --------------------------------------------------------- |
| GET   | `/api/v1/billing/status`     | Статус доступа и период подписки                          |
| POST  | `/api/v1/billing/checkout`   | Ссылка на счёт Stars; ограничение частоты                 |
| POST  | `/internal/telegram/webhook` | Команды, повторная проверка, оплата и обновления подписки |

Создание счёта закрыто при цене 0 и требует принятия актуальных документов.
До чтения входящего события проверяется `X-Telegram-Bot-Api-Secret-Token`.
Идентификатор события и платёж защищены от повторной обработки. Валюта должна быть `XTR`;
владелец, данные счёта и сумма сверяются с серверной записью.
Поддерживаются `/privacy`, `/terms`, `/paysupport <сообщение>`.

При настроенном защищённом обработчике повторная проверка предлагает `up`, `back`, `drowsy`.
Проверяются владелец личного чата и запись отправленного сообщения с совпадающими сессией
и идентификатором Telegram. Первое наблюдение сохраняется, повтор его не меняет.
Без обработчика остаётся переход в приложение. Сбой подтверждения Telegram после записи
не откатывает сохранённый ответ.
