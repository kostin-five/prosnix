# Handoff 066 — обновление очищенной истории на GitHub

## Разрешение и внешние проверки

7 октября владелец разрешил обновить очищенную dev, проверить CI и перенести её в master.
Перед push владелец отключил Auto-Deploy обоих сервисов Render. API показывает Off;
для сайта отключение подтверждено владельцем. Production deploy не входит в этот этап.

Remote содержит только dev и master, без tags и PR refs в ответе ls-remote.
Оба прежних SHA присутствуют в карте преобразования истории; чужих новых commits нет.
Очищенная dev отправлена через force-with-lease с явным ожидаемым SHA.
Первый CI для 7245eec: https://github.com/kostin-five/prosnix/actions/runs/37628084463.

## Порядок завершения

Этот документационный commit также отправляется в dev. Дождаться зелёных verify, security
и secrets для её окончательного SHA; затем fast-forward master до этого же SHA и отправить
master через force-with-lease с проверенным прежним SHA. В ответе владельцу указать итоговый
SHA и результат CI обеих веток. При ошибке CI сначала исправить dev и повторить gate.
Не возвращать старую историю через pull или merge. Не выполнять push --mirror.

## Проверки и границы

Локальные проверки очистки и неизменности кода описаны в handoff 065 и public-readiness.md.
Старые Actions runs сохраняют ссылки на прежние commits: force-push не удаляет кэши,
журналы, artifacts, forks или объекты GitHub, доступные по прежнему SHA. Для полной серверной
очистки нужен отдельный разбор этих данных и возможностей GitHub Support.
Публичность репозитория, размещение demo и выпуск live Mini App остаются отдельными решениями.
