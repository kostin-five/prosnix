# Design

## Context

См. [proposal.md](proposal.md). Follow-up уже имеет единственную серверную команду, запись с
уникальным `session_id` и отдельную delivery-таблицу с Telegram `message_id`. Telegram webhook
защищён секретным заголовком и сейчас обслуживает команды и платежи.

## Goals / Non-Goals

**Goals:** использовать тот же outcome и ту же команду, дать ответ одним нажатием, исключить
подделку владельца/чужого сообщения и безопасно выдержать повторную доставку Telegram.

**Non-Goals:** новый follow-up, изменение аналитической формулы, изменение webhook URL или secret,
новый worker либо таблица, автоматический ответ за пользователя.

## Decisions

### 1. Кнопки несут только ссылку на сессию и outcome

`callback_data` имеет короткий формат `fu:1:<session-uuid>:<u|b|d>` (не более 64 байт). ID и
outcome из кнопки не доверяются: webhook проверяет secret, `callback_query.from.id`, личный chat ID,
формат данных, запись отправленного follow-up с точным `message_id` и владение сессией. Отдельная
подпись в кнопке не нужна, так как подтверждение Telegram и доставка сверяются сервером.

### 2. Одна команда, один исходный ответ

Callback handler получает внутренний user ID через существующий `UserRepository`, проверяет
delivery через `FollowUpNotificationRepository` и вызывает `SessionService.execute` с
идемпотентным ключом из Telegram callback ID. Эта команда использует существующую транзакцию,
уникальный follow-up и блокировку по пользователю. При повторном ответе handler возвращает
безопасное «Ответ уже сохранён» и не перезаписывает наблюдение. Сырые update, ID и выбранный
outcome не логируются.

### 3. Текущий webhook и деградация

Обработка callback встроена в уже защищённый `/internal/telegram/webhook` перед командами и
платежами; остальные update продолжают прежний путь. Gateway отправляет три callback-кнопки только
при настроенном webhook secret и доступной обработке, иначе оставляет прежнюю кнопку Mini App.
После принятой команды gateway отвечает на callback и пытается убрать клавиатуру сообщения. Если
Telegram API недоступен, ответ в БД остаётся принятым; повторное нажатие безопасно. Новый webhook
или его переключение этим change не выполняются.

## Risks / Trade-offs

- [Нажатие раньше фиксации delivery] → безопасный отказ и возможность нажать повторно или открыть
  Mini App; отправка сообщения не считается записью follow-up.
- [Webhook не настроен в среде] → остаётся прежняя кнопка открытия Mini App.
- [Telegram API не подтвердил callback после DB commit] → повторное нажатие читает уже принятый
  ответ и не меняет его.
- [Старые сообщения] → прежняя кнопка Mini App сохраняет совместимость.

## Migration Plan

Новой migration нет. Код и contract/integration проверяются локально на disposable PostgreSQL.
Перед выпуском требуются зелёный CI точного SHA, проверка существующего Telegram webhook и ручной
smoke на iOS/Android. Любая смена webhook/secret/production среды требует отдельного разрешения
владельца. Rollback кода возвращает прежнюю кнопку для новых сообщений; уже принятые ответы остаются.
