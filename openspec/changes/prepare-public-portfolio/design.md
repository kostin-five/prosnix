## Context

Аудит текущего HEAD обнаружил утечку синтетического ответа через сообщение DrizzleQueryError. Проверки без DATABASE_URL пропускали интеграционные тесты. Файлы App.tsx и sessions.ts превышали 1000 строк.

## Goals / Non-Goals

Сохранить пользовательские сценарии и API; подготовить воспроизводимое портфолио и безопасные проверки. Не менять алгоритм обучения, платежи и инфраструктуру production.

## Decisions

- Логи используют разрешённые поля: метод, путь без query, статус и класс ошибки; сообщение, stack, cause и SQL-параметры исключаются.
- Production требует явно заданную БД и непустые неплейсхолдерные секреты.
- Отдельный Vite mode portfolio компилирует демо, блокирует API и игнорирует Telegram identity. Обычная production-сборка не включает демо.
- Модули разделяются по ответственности; facade сохраняет существующие импорты. Ограничение 1000 строк распространяется на исходный код, не на generated migrations и lockfile.
- Интеграционные тесты допускаются только с явной локальной тестовой БД.
- Шрифты поставляются локально с лицензией.

## Risks / Trade-offs

Обновление Vitest требует полного прогона. Перемещение файлов из текущего дерева не удаляет их из истории. Secret scan не гарантирует отсутствие данных в изображениях. Демонстрационные результаты не являются доказательством полезности приложения.

## Migration Plan

Локальные изменения, проверки на отдельной БД, полный отчёт владельцу. Production deploy и смена публичности отдельно.

## Open Questions

Владелец согласовал MIT для кода и собственных материалов, включая логотип. По решению от 7 октября используется текущий репозиторий prosnix с существующей историей. Отдельная копия не используется для выпуска. Локальная история очищена по разрешению владельца; удалённые refs, GitHub caches и forks требуют отдельного обновления/проверки перед публичностью.

## Уточнение: очистка истории

Разрешена владельцем 7 октября в текущем checkout, без новой копии. git-filter-repo удаляет
ненужные пути, заменяет личные сведения в blobs/messages и обезличивает commit metadata.
Перед преобразованием сохраняются hash кода, migrations и README, после — сравниваются.
Все доступные локальные refs преобразуются; старые reflog/недостижимые объекты удаляются.
Remote fetch/force-push и GitHub cache cleanup не входят в локальное разрешение.
