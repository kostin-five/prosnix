# Design

## Context

См. `proposal.md`. Сегодня сервер назначает шаги при создании сессии, принимает каждый результат
с idempotency key и `If-Match`, а Mini App показывает таймер в `ConfirmTask`. Текущие экранные
когнитивные задания требуют касаний. Звук использует Web Audio только в открытом WebView. Сессия
содержит JSONB снимок experience; task observations хранятся отдельно в PostgreSQL.

## Goals / Non-Goals

**Goals:** сохранить серверное назначение и переходы; обозначать автоматическое завершение
отдельно от ручного; не требовать микрофон; поддержать возобновление сессии после прерывания.

**Non-Goals:** системный будильник, гарантированный звук при закрытом Telegram или заблокированном
устройстве, распознавание речи, доказательство физического действия, изменение аналитических
формул или AI.

## Decisions

1. **Режим задаётся при создании сессии.** Расширить create-контракт `interactionMode` с
   совместимым значением по умолчанию `manual`; хранить его в существующем JSONB experience.
   Назначение для `hands_free` строить в домене из допускаемых неэкранных task IDs, в рамках
   существующего модульного монолита. Обычный планировщик не менять. Новые `notice_three` и
   `find_color` дают варианты без оборудования; первые версии используют существующие категории и
   честный `limited_eligible_tasks` при коротком списке.
2. **Запись источника завершения.** Добавить `completion_source` в `task_observations` новой
   forward-only миграцией с default `manual`; включить поле в серверный результат и доменную
   модель. Сервер разрешает `timer` только для hands-free неэкранного шага и требует минимальную
   длительность по политике задания; успешность остаётся наблюдением выбранного пользователем
   режима, не доказательством движения. Исторические записи читаются как `manual`.
3. **Звук на клиенте.** Использовать встроенный `speechSynthesis` для текста, существующий Web
   Audio для тихой атмосферы и трёх коротких сигналов. Аудио запускается только после жеста
   пользователя; при отсутствии API показать ограничение и оставить экранный путь. Историю
   подробных подсказок хранить локально под уже существующим user-scoped ключом, сбрасывать из
   настроек. Отказ от удалённого TTS защищает ответы и не добавляет provider.
4. **Автопереход после серверного принятия.** `ConfirmTask` управляет монотонным отсчётом и паузой;
   по истечении отправляет `timer` один раз через существующий gate. После успешного обновления
   сессии клиент озвучивает следующий шаг, ждёт 10 секунд и запускает его. При конфликте
   перезагружает каноническую сессию и требует повторного жеста. При `visibilitychange` таймер
   останавливается, чтобы скрытый WebView не записывал шаг.
5. **Пауза в обычном режиме.** Кликабельным делается только уже видимый таймер; ручная кнопка
   «Готово» остаётся. Тесты должны проверять отсутствие завершения во время паузы и маленький
   экран.

## Risks / Trade-offs

- [WebView ограничивает autoplay/TTS] → запускать звук после жеста, показывать ограничение и
  проверять вручную в Telegram iOS/Android; работа в фоне не обещается.
- [Таймер не доказывает действие] → отдельный `completion_source=timer`, понятный текст в UI,
  сохранение исходных оценок и формул без переименования данных в «проверенные».
- [Мало допустимых заданий] → планировать только разрешённые шаги и показывать фактическую оценку
  времени; не добавлять противопоказанное ради заполнения бюджета.
- [Повтор из-за сети или возобновления] → существующие idempotency key и версии, переход только
  после серверного подтверждения.

## Migration Plan

Новая миграция добавляет `completion_source` с default `manual`; старые записи остаются читаемыми.
Выпуск требует disposable PostgreSQL `verify:release:full`, зелёного CI точного SHA и ручного
Telegram smoke. Откат кода не откатывает миграцию; старый код игнорирует новый столбец.
